# 会議スケジュールへの議題追加

## 目的・背景

会議の予定内容を事前に簡単に共有したいという要望があった。現状のスケジュールはタイトルとトピック(タグ)のみで、予定内容を文章で記載する欄がない。

## 確定要件

- **入力**: 管理画面のスケジュール作成・編集フォームに「議題」欄を追加する。任意入力の複数行テキストとする。
- **保存**: 前後の空白を除去して保存する。空の場合は未設定として扱う。
- **表示箇所**: `/schedule` の各回カード(今後の予定・開催済みの回の両方)と、トップページの次回予定。
- **表示方式**: 展開式とする。「議題」を押すとその場で開閉し、初期状態は閉じている。
- **本文の表示**: 改行を保持したプレーンテキストとして表示する。HTML・Markdown は解釈しない。
- **未入力の回**: 議題の開閉要素を表示しない。
- **既存項目**: トピック(タグ)は変更せず併存させる。
- **見た目の確認**: 実装の途中でユーザーが画面を確認し、指摘を反映する。
- **本番 D1**: `schedule` テーブルへの列追加は Admin が実施する(エージェントはコマンドの提示まで)。
- **更新履歴**: 一般ユーザーの表示が変わるため `app/utils/changelog.ts` に追記する。

### 対象外

- 議題の別ページ表示・モーダル表示
- 議題の Markdown 対応
- チャット画面・管理画面のスケジュール一覧での議題表示
- 議題の議事録への連携

## 受入条件

1. 管理画面で議題を入力して保存すると、再編集時に同じ内容(改行を含む)が表示される。
2. 議題のある回は `/schedule` のカード(今後の予定・開催済みの回)に「議題」の開閉要素が表示され、開くと改行を保持した本文が表示される。
3. トップページの次回予定でも、議題のある回は同様に開閉して本文を確認できる。
4. 議題が未入力の回には開閉要素が表示されない。議題を空にして保存すると未設定に戻る。
5. 議題本文に含まれる HTML タグは解釈されず、文字列として表示される。
6. 議題以外の既存項目(トピック・開催場所・会議URL 等)の保存と表示に変化がない。議題列の追加前から存在する回も正常に表示される。
7. `npm test` と `npm run check` が通る。
8. 見た目についてユーザーの確認を得ている(ユーザー実施)。
9. 本番 D1 への列追加後、本番環境で議題の保存と表示ができる(実環境・ユーザー実施)。

## 仕様書反映

スケジュール機能の恒久仕様書が存在しないため、`docs/requirements-schedule.md` を最小限の内容で新規作成する。

### 追加: スケジュールの項目

- 開催日・開催時間・タイトル(必須)、トピック・開催場所・会議URL・議題(任意)。

### 追加: 議題

- 入力・保存・表示箇所・表示方式・未入力時の扱い(確定要件のとおり)。
