# T-019 実装計画

## 設計判断

- **スキーマ**: `db/schema.sql` に次のテーブルを追加する。
  ```sql
  CREATE TABLE IF NOT EXISTS todos (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    title        TEXT NOT NULL,
    assignee     TEXT,
    due_date     TEXT,
    minutes_slug TEXT REFERENCES minutes(slug) ON DELETE SET NULL,
    done_at      TEXT,
    created_at   TEXT DEFAULT (datetime('now')),
    updated_at   TEXT DEFAULT (datetime('now'))
  );
  ```
- **状態の持ち方**: 完了は `done_at`(完了にした日時)の有無で表す。完了フラグの列を別に持つ方式は、フラグと日時の2か所を同期させる必要があるため採らない。
- **議事録の紐付け**: `minutes_slug` に外部キー(`ON DELETE SET NULL`)を付ける。議事録を削除すると紐付けが DB 側で解除され、存在しない議事録の指定も DB が拒否する。アプリ側に解除処理を追加しない。`node:sqlite` のインメモリ DB に現行の `db/schema.sql` と本テーブルを適用し、議事録の削除で `minutes_slug` が NULL になること、存在しない slug の登録が拒否されることを事前に確認した。議事録の slug は開催日で、変更できない(更新処理が拒否する)ため、`ON UPDATE` の指定は不要。検討した代替案は次のとおり。
  - 外部キーを付けず slug のみ保持する(既存の発表応募・資料と同じ方式): 削除後も slug が残り、同じ開催日の議事録を作り直すと紐付けが復活する。「紐付けのみ解除」の要件と合わないため採らない。
  - 議事録の削除処理に解除の SQL を足す: 削除経路ごとに処理が要り、漏れると不整合になるため採らない。
  - 議事録の ID を参照する: 既存の一覧 API と絞り込み(`minutesSlug`)が slug を軸にしており、ID を返す変更が別途必要になるため採らない。
- **並び順**: SQL で決める。未完了は `id` の降順、完了済みは `done_at` の降順(同値は `id` の降順)。登録順の判定に `created_at` を使わないのは、書き込み元によって日時の形式が混在し得るため(発表応募で生じた問題と同じ)。`done_at` はアプリが常に ISO 8601 で書き込むため、文字列の比較で順序が決まる。
- **サーバ処理**: `server/utils/todos.ts` に一覧・登録・更新・削除と入力検証を置く。
  - 件名は前後の空白を除去し、空は 400。上限 200 文字。
  - 担当は前後の空白を除去し、空は未設定として扱う。上限 50 文字。
  - 期限は `YYYY-MM-DD` 形式のみ受け付ける。空は未設定。
  - 議事録は存在を確認し、存在しない slug は 400。空は未設定。
  - 文字数の上限は確定要件に無いため、G2 で併せて確認する。上限の値は `shared/utils/todos.ts` に置き、入力欄の `maxlength` と共用する。
- **API**:
  - `GET /api/todos`: 全利用者。未完了・完了済みの全件を返す。`minutesSlug` を指定すると、その議事録に紐付く課題のみを返す(既存の `/api/resources?minutesSlug=` と同じ形)。議事録のタイトルは `minutes` との LEFT JOIN で併せて返す。
  - `POST /api/admin/todos`、`PUT /api/admin/todos/{id}`、`DELETE /api/admin/todos/{id}`: 先頭で `assertAdmin` を呼び、管理者以外は 403。
  - `PUT` は部分更新とし、項目の編集と完了の切り替え(`done`)を同じ API で扱う。完了の切り替え専用の API は設けない。完了にすると `done_at` に現在時刻を入れ、未完了へ戻すと NULL にする。既に完了している課題を再度完了にしても `done_at` は変えない。
  - 完了済みを含む全件を一度に返す。完了済みが数百件規模になった場合は、完了済みを展開時に取得する方式へ切り替える(その時点で対応する)。
- **期限超過の判定**: `shared/utils/todos.ts` に純粋関数として置く(未完了、かつ期限が今日より前)。今日の日付は `jstToday()` で求める。サーバ側の描画は UTC で動くため、ローカル時刻から求めると、日本時間の0時から9時の間にサーバとブラウザで結果が分かれる。
- **型**: `types/portal.ts` に `Todo`(`id`、`title`、`assignee`、`dueDate`、`minutesSlug`、`minutesTitle`、`doneAt`)と `TodosResponse` を追加する。
- **課題ページ**: `app/pages/todos.vue`(URL は `/todos`)。追加欄と、追加の API の呼び出しを持つ。変更後は一覧を再取得する(画面側で先に書き換える方式は採らない)。
  - 管理者の判定は `useCurrentUser()` の `isAdmin` による。議事録の選択肢は既存の `/api/minutes`(開催日の降順)を、管理者のときだけ取得する。
  - 入力欄の配色は追加欄と行内編集で共用するため、`app/utils/ui.ts` に `inputClass` を追加する。
- **表の部品**: `app/components/todo/TodoTable.vue` に表を切り出し、課題ページと議事録ページの両方で使う。操作欄の有無と議事録の列の有無を props で切り替える。行内編集の状態と、完了の切り替え・保存・削除の API の呼び出しは部品が持ち、成功したら親へ通知して一覧を再取得させる。当初は API の呼び出しを親に置く計画だったが、保存に失敗したときに入力欄を開いたまま内容を残すには、呼び出しの結果を部品が知る必要があるため変更した。両ページに表を別々に書く方式は、列・期限超過の表示・取り消し線の指定が重複するため採らない。
  - 削除の確認は `confirm()` で行う(既存の `AdminDeleteButton.vue` と同じ方式。同部品は文字付きのボタンのため流用しない)。
  - 保存・削除に失敗した場合は、表の上にエラー文を表示する。編集中の入力欄は開いたまま残す。
  - チェックボックスは、押下時点では表示を変えず、再取得した一覧に従って表示する(失敗時に表示とデータが食い違わないようにするため)。
  - 未完了が0件で完了済みがある場合は、表に未完了の課題が無い旨を表示する。
  - 表の枠には位置指定(`relative`)を付ける。読み上げ専用の見出しは絶対配置のため、指定が無いと狭い画面でページ全体が横スクロールする。「完了済み」の行は、表を横スクロールしても見える位置に固定する。
  - 「完了済み(n件)」の開閉は部品が持つ。議事録ページでは折りたたまない指定にする。
  - 編集中の Enter キーと Esc キーは、日本語入力の変換中には反応させない(アンケートコメントの入力と同じ扱い)。
  - アイコンは既存の依存 `lucide-vue-next` を使う。
- **議事録ページ**: `app/pages/minutes/[slug]/index.vue` で `/api/todos?minutesSlug=` を取得し、本文の直下(既存の「関連資料」の上)に見出し「課題」と表、課題ページへのリンクを置く。0件のときは欄ごと表示しない。
- **ナビ**: `app/components/site/SiteHeader.vue` の項目を変更する。デスクトップとモバイルは同じ配列を使っているため、変更は1か所で済む。
- **本番適用**: 新規テーブルのみのため、`npm run db:schema:prod`(`CREATE TABLE IF NOT EXISTS`)で適用できる。Preview D1 は `npm run db:schema:preview`。案内する際は、DB 名の環境変数(`D1_DATABASE_NAME`・`D1_PREVIEW_DATABASE_NAME`)の指定を添える。
- **本番適用の順序**: 実装 PR の merge 前に適用する。現行コードは新テーブルを参照しないため、先に適用しても影響しない。逆順では、テーブルが無い間、課題ページと議事録の詳細ページの取得が失敗する。
- **テスト**: 並び順と外部キーの動作はモックでは検証できないため、`db/schema.sql` を `node:sqlite` のインメモリ DB に適用して確かめる。D1 の形に合わせる薄い変換はテストファイル内に置く(既存の `tests/survey-comments.test.ts`・`tests/speakers-server.test.ts` と同じ方式)。既存の2ファイルにも同種の変換が重複しているが、共通化は本タスクの対象外とする。
- **管理者以外の確認**: ローカルの認証処理は、Access の JWT ヘッダーがあればそのメールアドレスを利用者として扱う。管理者でないメールアドレスを載せたヘッダーを付けて、API の拒否と画面の表示を確認する(`.dev.vars` は変更しない)。
- **一時ページ**: `app/pages/mock-todos.vue` は実装時の見た目の参照元とし、課題ページの実装後に削除する。コミットには含めない。
- **更新履歴**: `feature` として1項目を追記する。課題ページの追加を主とし、ナビの名称変更(資料共有→資料、発表募集→発表)を説明に含める。
