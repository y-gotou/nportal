# T-023 実装計画

## 設計判断

### 文言・用語・記号の置き換え(確定要件 1〜6・8・11)

- 各画面のテンプレートに直書きされている文言を、そのまま置き換える。
- 再発を防ぐため、廃止した表記が `app/` 配下の `.vue` に残っていないことを検査するテスト(`tests/wording.test.mjs`)を追加する。対象は「チャットを見る」「資料を見る」「資料共有へ戻る」「発表者募集」「紐付けなし」「未選択」「予定一覧」「申し込」「エントリー」「登録されていません」、進行中表示の「...」、全角括弧。コメント行と更新情報(`app/utils/changelog.ts`)は検査しない。
- **不採用**: 文言を定数ファイルにまとめる案。各文言は 1〜3 か所でしか使われず、既存のコードも直書きで統一されている。間接参照を増やすより、テストで揃っていることを保証する。
- 必須マークは、色を `text-red-500` に統一する(アンケートの 2 か所が `text-rose-500`)。間隔は、空白が抜けている発表募集の「発表時間(分)」の 1 か所を直す。

要件書の受入条件の訂正: 資料の投稿フォームの項目名「関連議事録」は、議事録へ移動するボタンではなく入力項目の名前のため、変更しない。受入条件の「変更前の表記が残っていない」から、この項目名を除く。

### 0 件時の出し分け(確定要件 5)

- **資料一覧**(`app/pages/resources/index.vue`): 取得した資料が 0 件なら「資料はまだありません。」、絞り込みの結果が 0 件なら「条件に合う資料はありません。」を表示する。
- **議事録一覧**(`app/components/minutes/MinutesSearch.vue`): 絞り込みはサーバー側で行うため、URL の検索語(`q`)が空で 0 件なら「議事録はまだありません。」、検索語があって 0 件なら「条件に合う議事録はありません。」を表示する。

### 利用者の表示(確定要件 7)

- チャットで使っている既存の関数 `chatDisplayName`(`shared/utils/chat.ts`)を、発表募集のカード(`app/pages/speakers.vue`)と資料の投稿者(`app/pages/resources/index.vue`、`app/pages/resources/[id].vue`)でも使う。
- 資料の検索は、従来どおりメールアドレス全体を対象にする(検索対象は変更しない要件のため)。
- **不採用**: 表示名用の関数を新設する案。処理が同じため、既存の関数を再利用する。

### ボタンの配置(確定要件 9)

- ボタン群の要素に、横並びになる幅から並びを反転する指定(`sm:flex-row-reverse`。スケジュールは横並びが `lg` からのため `lg:flex-row-reverse`)を付ける。HTML 上の順序は変えないため、スマホ幅は現状の並びのままになる。
- 対象は 7 か所: 資料一覧、ホーム(受付中のアンケート・最近の資料)、スケジュール(今後の予定・開催済みの回)、アンケート一覧、発表募集。
- 留意点: PC 幅では、キーボードの Tab キーでの移動順が見た目と逆(右から左)になる。ボタンは 1 カードあたり最大 4 個で、操作に支障はないと判断する。
- **不採用(比較モックで検討済み)**: A1(主ボタンだけを右端へ移す)は「削除」が主ボタンの隣に来る。B(下段に左寄せ)はカードの高さが増える。
- **不採用**: PC 幅とスマホ幅で HTML の順序自体を入れ替える案。同じボタンを 2 通り書くことになり、文言の不揃いを再び生みやすい。

### 軽微なレイアウト(確定要件 10)

- **発表募集のボタンの大きさ**: 「編集」は `secondaryButtonClass` を使う。「取り下げ」は資料一覧の「削除」と同じ配色・大きさにする。この赤いボタンの指定は 2 か所で使うことになるため、`app/utils/ui.ts` に `dangerButtonClass` として切り出し、資料一覧の「削除」もこれを使う。
- **発表募集のカードの区切り**: 区切りの「|」の文字をやめ、各項目の左側の罫線で区切る。行の先頭に来た項目の罫線は、枠の外にはみ出させて隠す(CSS のみ。どこで折り返しても、行頭・行末に区切りが残らない)。
  - 不採用: 「・」でつないだ 1 つの文字列にする案。折り返すと「・」が行末に残る。
  - 不採用: 区切りをなくして余白だけにする案。項目の境目が分かりにくくなる。
- **発表募集の見出し**: 独自の横並びをやめ、資料一覧と同じく `SectionHeader` の action スロットに主ボタンを入れる。
- **資料一覧のタグ欄**: タグが 0 件のときは行ごと表示しない(`v-if`)。
- **議事録カード**: `MinutesSearch.vue` のカードの余白の指定を、ホームの「最近の議事録」と同じ値にする。日付に折り返さない指定(`shrink-0`)を付ける。
  - 不採用: ホームと議事録一覧のカードを 1 つの部品にまとめる案。重複は解消できるが、変更の範囲が要件(余白を揃える)を超える。重複が残る点は、既存の課題として作業ログに記録する。
- **検索パネル**: `MinutesSearch.vue` の検索パネルの背景と入力欄の指定を、資料一覧と同じ値にする。
- **ニュースの大見出し**(`app/pages/news.vue`): スマホ幅では、大見出しの下の段に「最終更新」を 1 行(「最終更新 10/2 07:00」)で表示する。640px 以上は従来どおり(見出しの右に 2 行)。
  - 不採用: スマホ幅で見出しの文字を小さくする案。360px 幅では、見出しと「最終更新」を横に並べたままでは収まらない。

### 管理画面(確定要件 11)

- 文言の置き換えのみ。ヒントの文言は、新規作成時が「カンマ区切り(例: …)」、編集時が「カンマ区切り」(現状どおり入力例を省く)とする。

### 更新情報

- `improvement` として 1 項目を追記する(文言の統一とボタンの並びを 1 つの伝達単位にまとめる)。
