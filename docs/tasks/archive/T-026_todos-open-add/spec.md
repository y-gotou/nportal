# 課題の追加を全利用者に開放

## 目的・背景

課題の追加・編集・削除・完了の切り替えは、T-019 で管理者のみの操作とした。利用者から、課題の追加を誰でもできるようにしたいとの要望があった。

管理者以外の利用者も課題を追加できるようにする。あわせて、追加した本人が自分の課題を直せるようにし、誰が追加した課題かを一覧で確認できるようにする。

## 確定要件

### 1. 追加

- ログイン済みの全利用者が、課題ページで課題を追加できる。
- 追加欄の項目は変更しない(件名・担当・期限・議事録)。追加時に「担当」へ登録者を自動で入力しない。

### 2. 登録者

- 課題を追加した利用者を、その課題の登録者として記録する。
- 登録者は、課題を編集しても変わらない(管理者による編集を含む)。
- 課題ページの表に「登録者」の列を追加する。位置は「議事録」の列の右とする。表示の形式は、資料一覧の「投稿者」と同じにする。
- 登録者の記録が無い課題は、登録者を空欄で表示する。

### 3. 操作の権限

| 利用者 | 追加 | 編集・削除・完了の切り替え |
| --- | --- | --- |
| 管理者 | できる | すべての課題に対してできる(変更なし) |
| 管理者以外 | できる | 自分が登録した課題に対してのみできる |

- 管理者以外には、自分が登録した課題以外の行に編集・削除のアイコンを表示しない。チェックボックスは操作できない状態で表示する。
- 登録者の記録が無い課題を操作できるのは、管理者のみとする。
- 権限の無い編集・削除・完了の切り替えの要求は、サーバーが拒否する。

### 4. 議事録ページ

- 議事録の詳細ページの課題表は変更しない。登録者の列は表示せず、操作もできないままとする。

### 5. 既存の課題

- データの移行は行わない。本番反映後に、ユーザーが既存の課題を削除して登録し直す。

### 対象外

- 担当欄に書かれた本人による編集・完了(担当は自由入力で、利用者のアカウントと対応付けていないため)
- 登録者の変更・引き継ぎ
- 「自分の課題」の絞り込み
- 議事録ページでの課題の操作

## 受入条件

1. 管理者以外の利用者が課題を追加でき、一覧の登録者に自分が表示される。
2. 管理者以外は、自分が登録した課題のみ編集・削除・完了の切り替えができる。他人の課題には操作のアイコンが表示されず、チェックボックスは操作できない。
3. 管理者以外による他人の課題への編集・削除・完了の切り替えの要求を、サーバーが拒否する。
4. 管理者はすべての課題を操作でき、他人の課題を編集しても登録者は変わらない。
5. 登録者の記録が無い課題は、登録者が空欄で表示され、管理者のみ操作できる。
6. 議事録ページの課題表は変わらない。
7. `npm test` と `npm run check` が通る。
