# 発表者募集モーダルの誤クローズ対策

## 目的・背景

発表者募集ページ(`app/pages/speakers.vue`)の申し込み・編集モーダルは、オーバーレイの `@click.self` により外側クリックで入力内容の有無にかかわらず即座に閉じる。入力途中の内容が警告なく失われるため UX に問題がある。資料ページ(`app/pages/resources/index.vue`)には dirty 判定 + 確認ダイアログの対策済みパターンが存在し、これに統一する。

要件は 2026-08-20 のユーザーヒアリングで確定済み。

## 確定要件

1. 外側クリック時、入力あり(dirty)なら確認ダイアログ「入力中の内容は保存されていません。閉じてもよろしいですか？」を表示し、OK で閉じる・キャンセルで維持する。未入力なら従来どおり即閉じる。
2. キャンセルボタン押下時にも同じ確認ルールを適用する。
3. 送信成功時は従来どおり確認なしで閉じる。
4. dirty の定義は初期値からの変化とする(新規: タイトル空・発表時間 15・備考空 / 編集: 読み込んだ応募値)。入力後に手動で初期値へ戻した場合は dirty と見なさない。
5. 方式・確認文言は資料ページの既存パターンに統一する。
6. スコープ外: Esc キー対応は行わない。ドラッグ選択誤クローズへの追加ガード(mousedown 起点判定)は導入しない(資料ページと同挙動に揃える)。
7. 対応範囲は発表者募集モーダルのみ。点検の結果、資料ページは対策済み、ChatImageModal・SiteHeader・admin layout のオーバーレイは入力を伴わず対象外。

## 受入条件

- 未入力状態で外側クリックすると確認なしで閉じる。
- 入力途中に外側クリックまたはキャンセルボタン押下で確認ダイアログが表示され、キャンセルするとモーダルと入力内容が保持され、OK すると閉じる。編集モーダルでは読み込み値から変更した場合のみ確認が出る。
- dirty 判定ロジックのユニットテストが追加され、`npm test` と `npm run check` が通過する。

## 仕様書反映

対象機能の要件文書が存在しないため、`docs/requirements-speakers.md` を最小限の内容で新規作成する(_config.md の方針に従う)。
