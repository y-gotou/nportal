## 時系列ログ

- 2026-09-01: ナレッジベース機能のヒアリングを実施(起票前)。N Portal 内の一機能とすること、記事の構成要素(タイトル・概要文・Markdown 本文・カテゴリ 1 件・タグ・関連勉強会回)、全員投稿で編集削除は本人と管理者、即公開・物理削除、LIKE 検索とカテゴリ・タグ絞り込み、画像はチャットと同一制限で R2 保存、トップページに新着表示、投稿者表示は user_email ベースであることを確定。RAG・LLM 執筆支援・初期データ取り込みは対象外とした。
- 2026-09-02: 起票。規模を大規模と判定(新規テーブル複数・新規画面複数・恒久仕様書の新規作成・段階リリース)。ヒアリング時点の未確定点について次のとおり決定。
  - Markdown プレビュー方式: サーバー変換 API(`POST /api/knowledge/preview`)を新設し、議事録と同一の remark パイプラインを用いる。クライアントへの Markdown ライブラリ追加案は、依存追加とサニタイズ実装が別途必要になること、保存後のサーバー変換結果とレンダリング差異が生じうることから採らない。
  - カテゴリ配色: `app/utils/` の固定パレットから選択し、DB には配色キーのみを保持する。表示用の配色を `app/utils/` に集約するプロジェクト規約に従う。
  - 実装の段階: 2 段階に分割(第 1 弾=記事 CRUD・カテゴリ・Markdown、第 2 弾=タグ・検索・画像・連携・新着)。
  - 本文画像の保存方式: `knowledge_images` テーブルで記事との対応を管理する(資料機能の `resource_images` と同方式)。R2 キーを本文へ埋め込むだけの案は、記事削除時に孤児ファイルが残るため採らない。
  - 既定値として提示し異論がなかった項目: URL は `/knowledge`、文字数上限はタイトル 100 / 概要文 200 / 本文 50,000 文字。
- 2026-09-02: ユーザー指示により、実装着手前に Artifact でモックアップを提示し確認を得るフェーズを設けることとした。plan.md の作業項目に含める。
- 2026-09-02: G1 承認。plan.md 作成。既存資産の調査結果として、`renderMarkdown` と `escapeLikePattern` が `server/utils/minutes.ts` に既にあること、資料機能の Markdown 投稿が multipart で本文と画像を同時送信し表示時に `resolveMarkdownImageSources` で src を解決する方式であることを確認し、いずれも共通化して再利用する方針とした。
