# ナレッジベース(PoC)

## 目的・背景

勉強会メンバーが得た知見(How-to / 用語集 / 学習メモ)は、現状チャットや議事録に散在しており、後から参照する導線がない。N Portal 内に記事形式のナレッジベースを設け、メンバー全員が投稿・参照できるようにする。

本タスクは PoC として位置づける。評価軸は次の 2 点。

1. 勉強会メンバーの投稿・参照が習慣として定着するか。
2. 将来的な RAG(記事を参照する AI 応答)のデータ基盤として成立するか。

2 点目のため、本文はプレーンな Markdown で保持し、概要文を必須とする。

## 確定要件

### 位置づけ・利用者

- N Portal 内の一機能とし、URL は `/knowledge` 配下に置く。
- 利用者は勉強会メンバー(既存の認証を通過したユーザー全員)。

### 記事

- 記事は次の項目を持つ。
  - タイトル(必須、100 文字以内)
  - 概要文(必須、200 文字以内)
  - 本文(必須、Markdown、50,000 文字以内)
  - カテゴリ(必須、1 件)
  - タグ(任意、複数)
  - 関連する勉強会回(任意、`schedule` から 1 件)
- 投稿は全ユーザーが行える。編集・削除は投稿者本人と管理者のみ。
- 下書き・公開日時指定は設けず、投稿時点で即公開する。
- 版管理(編集履歴)、リアクション、コメントは設けない。
- 削除は物理削除とし、確認ダイアログを挟む。
- 投稿者の表示はチャットと同様に `user_email` を基準とする。

### 本文の編集とプレビュー

- 編集画面はエディタとプレビューを並置する。
- プレビューは本文を `POST /api/knowledge/preview` へ送り、サーバー側で議事録と同一の remark パイプライン(remark + remark-gfm + remark-html)により HTML へ変換した結果を表示する。入力停止からのデバウンスを挟む。
- 保存済み記事の表示にも同一のパイプラインを用い、プレビューと表示結果を一致させる。

### カテゴリ

- カテゴリは管理画面で管理者が追加・変更・削除する。
- 配色は `app/utils/` に固定パレット(トークン)を定義し、カテゴリには配色キーのみを保持する。管理画面ではパレットからの選択とする。
- 記事が 1 件以上属するカテゴリは削除できない。

### タグ

- 入力は自由入力とし、既存タグを候補として表示する。
- 登録時に正規化(前後空白の除去、全角英数の半角化、英字の小文字化)を行い、正規化後に一致するタグは同一として扱う。

### 検索・一覧

- 一覧は更新日の降順で表示する。
- キーワード検索はタイトルと本文に対する LIKE 検索とする。
- カテゴリ・タグによる絞り込みを併用できる。

### 画像

- 本文中の画像は R2 に保存し、`knowledge_images` テーブルで記事との対応を管理する(資料機能の `resource_images` と同方式)。
- 形式・サイズの制限はチャットの画像投稿と同一とする。
- 編集画面へのペーストおよびドラッグ&ドロップでアップロードできる。
- 記事削除時は対応する画像も削除する。

### 他機能との連携

- 記事と勉強会回(`schedule`)は双方向に表示する。記事詳細に勉強会回へのリンクを、勉強会回側に関連記事の一覧を置く。
- トップページに新着記事を表示する。

### 実装の段階

第 1 弾と第 2 弾に分け、それぞれ別 PR とする。

- **第 1 弾**: 記事の CRUD、カテゴリ管理、Markdown 本文とプレビュー、一覧・詳細表示。
- **第 2 弾**: タグ、キーワード検索と絞り込み、画像アップロード、勉強会回との連携、トップページの新着表示。

### 進め方

- 実装着手前にモックアップを Artifact として作成し、ユーザーの確認を得る。画面構成・情報設計に対する指摘を反映してから実装に入る。

## 対象外

- RAG(ナレッジ記事を参照する AI 応答)。本タスクではデータ構造の前提を整えるに留める。
- LLM による執筆支援(要約生成・タイトル案の提示など)。
- 既存資料・議事録からの初期データ取り込み。
- 下書き保存、編集履歴、リアクション、コメント。
- 記事の並び替え条件の選択(更新日降順で固定)。

## 受入条件

### 第 1 弾

- [ ] `/knowledge` で記事一覧が更新日の降順で表示され、各記事のタイトル・概要文・カテゴリ・投稿者・更新日を確認できる。
- [ ] 認証済みユーザーが記事を新規投稿でき、タイトル・概要文・本文・カテゴリの未入力時はエラーとなる。各項目の文字数上限を超える入力は拒否される。
- [ ] 編集画面でエディタとプレビューが並置され、入力に応じてプレビューが Markdown の変換結果へ追随する。GFM の表・チェックリストが変換される。
- [ ] 記事詳細の本文表示がプレビューと同一のレンダリング結果になる。
- [ ] 記事の編集・削除が投稿者本人と管理者のみ可能で、他ユーザーには操作 UI が表示されず、API も 403 を返す。
- [ ] 削除は確認ダイアログを経て実行され、記事が物理削除される。
- [ ] 管理画面でカテゴリを追加・変更・削除でき、配色は固定パレットから選択する。記事が属するカテゴリの削除は拒否される。

### 第 2 弾

- [ ] 記事にタグを自由入力で付与でき、入力中に既存タグが候補表示される。正規化により表記ゆれのあるタグが同一として扱われる。
- [ ] 一覧でキーワード検索(タイトル・本文の LIKE)とカテゴリ・タグの絞り込みを併用でき、結果が更新日降順で表示される。
- [ ] 編集画面で画像をペーストまたはドロップするとアップロードされ、本文へ Markdown の画像記法が挿入されて表示される。チャットと同一の形式・サイズ制限が適用される。
- [ ] 記事削除時に、その記事に紐づく画像が R2 と `knowledge_images` の双方から削除される。
- [ ] 記事詳細から関連する勉強会回へ遷移でき、勉強会回の側にも関連記事が一覧表示される。
- [ ] トップページに新着記事が表示され、記事詳細へ遷移できる。
