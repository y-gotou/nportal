# 発表者募集機能 要件定義書

- 作成日: 2026-08-20
- 更新日: 2026-08-31(T-011 資料の紐付けを反映)
- ステータス: 実装完了・運用中

## 1. 背景・目的

社内 AI 勉強会の発表者を募集し、応募状況(応募中・発表予定・発表済み)を参加者が一覧できる場を N Portal 上に設ける。

## 2. 機能概要

- 発表者募集ページ(`/speakers`)で応募一覧をステータス別(応募中・発表予定・発表済み)に表示する。
- ログインユーザーはモーダルフォームから発表を申し込める(発表テーマ・タイトル、発表時間(分)、備考・コメント)。
- 応募者本人は応募内容の編集・取り下げができる。取り下げ時は確認ダイアログを表示する。
- 議事録が紐付けられた応募には、カードに該当議事録へのリンクを表示する(§4)。
- 応募に発表資料を 1 件紐付けられる。紐付けた応募のカードには資料へのリンクを表示する(§5)。

## 3. 申し込み・編集モーダルの閉じる操作

- 閉じる手段はオーバーレイ(モーダル外側)のクリックとキャンセルボタンの2つ。Esc キーには対応しない。
- いずれの手段でも、フォームが初期値から変更されている場合は確認ダイアログ「入力中の内容は保存されていません。閉じてもよろしいですか？」を表示し、OK で閉じる・キャンセルでモーダルと入力内容を維持する。未変更なら確認なしで閉じる。
- 初期値は、新規申し込みではタイトル空・発表時間 15・備考空、編集では読み込んだ応募値とする。入力後に手動で初期値へ戻した場合は未変更として扱う。
- 送信成功時は確認なしで閉じる。
- 確認の方式・文言は資料ページの投稿モーダルと共通とする。

## 4. 発表済み申込と議事録の紐付け

- `speaker_applications.minutes_slug`(NULL 許容)で発表回の議事録と紐付ける。
- 紐付けは管理画面の発表募集管理ページで行う。ステータスの右の議事録ドロップダウン(「紐付けなし」+議事録一覧の日付降順)で管理者が手動設定し、発表が終わった際に更新する運用とする。
- 発表募集ページのカードには、`minutes_slug` が設定されている場合のみ「議事録を見る」リンク(`/minutes/{minutes_slug}`)を表示する。未設定なら表示しない。
- 一般ユーザー用の編集 API では `minutes_slug` を受け付けない(管理者用 API のみ)。

## 5. 応募と発表資料の紐付け

### 紐付けモデル

- `speaker_applications.resource_id`(NULL 許容)で資料共有の資料と紐付ける。
- 応募 1 件に資料 1 件、資料 1 件に応募 1 件の 1 対 1 とする。UNIQUE インデックスで重複紐付けを禁止し、他の応募に紐付け済みの資料を指定した場合は 409 を返す。
- 紐付ける資料は資料共有に投稿済みのものから選択する。応募フォームからの資料の新規投稿は行わない。

### 操作権限

- 応募者本人は、発表者募集ページの自分の応募カードにある資料セレクトから設定・変更・解除できる。候補は自分が投稿した資料(`resources.submitted_by` が本人)に限る。他人が投稿した資料を指定した場合は 403 を返す。
- 管理者は、発表募集管理ページのセレクトから全資料を対象に設定・変更・解除できる。
- 資料の紐付けは応募ステータスを問わず行える。発表済み(`done`)の応募は本人による編集・取り下げができない(§2)が、資料の紐付けはこの制限の対象外とし、発表後の資料掲載を可能にする。そのため紐付けは編集モーダルではなくカード上のセレクトで行う。

### 表示

- 応募カードには、`resource_id` が設定されている場合のみ「資料を見る」リンクを表示する。未設定なら表示しない。
- リンクの開き方は資料の種別に従う([requirements-resources.md](requirements-resources.md)「資料を開くリンク」)。

### 資料側項目の自動反映

- 紐付けの設定・更新時、および管理者による応募の更新時に、紐付いた資料の `presenter` と `related_minutes_slug` が未設定(NULL または空文字)であれば、それぞれ応募者のメールアドレスと応募の `minutes_slug` を反映する。
- 設定済みの値は上書きしない。

### 資料削除時

- 紐付いている資料の削除は許可し、削除時に該当応募の `resource_id` を NULL に戻して紐付けを自動解除する。
